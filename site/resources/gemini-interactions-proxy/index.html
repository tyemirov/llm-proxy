Gemini Interactions proxy for stored 3.x model calls

Route two registered Gemini 3.x models through stored Interactions with provider-configured visibility retries, cleanup, and one blocking proxy request.

Developers adding Gemini as a provider without bringing Gemini-specific payloads into every app.

Reviewed 2026-08-22 by Tyemirov on GitHub.

Quick verdict

Use this route for two registered Gemini 3.x models when the proxy must own stored-resource polling, visibility retries, and cleanup.

Open API reference Browse all resources

The problem

Stored Gemini Interactions require polling and cleanup, which shared proxy callers must not have to coordinate.

How LLM Proxy helps

LLM Proxy polls and cleans up registered Gemini 3.x resources while callers keep one blocking request.

How it works

  1. Keep the Gemini transport and offerings in providers.yml, then save the Gemini API key in tenant settings.
  2. Select provider=gemini or set Gemini as a tenant default.
  3. Send canonical messages through /v2 or compatibility text requests.
  4. Keep max_tokens within configured Gemini output limits.

Feature-to-benefit table

Feature Why it matters here Example
Native adapter The backend maps user messages into Gemini interaction steps. System instructions use Gemini's system_instruction shape, and assistant history is invalid.
Resource lifecycle The proxy polls queued and in-progress Gemini 3.x interactions server-side. Active resources are cancelled and every stored interaction is deleted on exit.
Tenant defaults Omitted model uses the tenant's saved Gemini text model. Client code can omit the model while tenant settings remain authoritative.
Output limit contract Gemini max_tokens values above configured limits return 400 before upstream calls. An incomplete interaction returns a provider error without replay.

Use-case examples

Gemini summary

A service sends provider=gemini and omits model to use the configured default.

Long user input

A /v2 request routes user messages through Gemini without a Gemini SDK.

Limit check

A caller sets max_tokens inside the configured Gemini limit.

Objections and limitations

  • Gemini dictation is not exposed through /dictate in this repo.
  • Web search is not marked supported for Gemini in the current proxy catalog.
  • Each Gemini Interactions route rejects assistant history.
  • The Gemini model list must be maintained in providers.yml.

FAQ

Which Gemini models does this route register?

The catalog registers Gemini 3.5 Flash and Gemini 3 Flash Preview.

Can a Gemini request contain assistant history?

No. Each Gemini Interactions route rejects an assistant message before it sends an upstream request.

What happens when Gemini returns an incomplete interaction?

The proxy cleans up the stored interaction and returns a provider error. It does not replay the partial output.

How does the proxy handle delayed Gemini resource visibility?

The Gemini transport declares six retries at five-second intervals for HTTP 400, 403, and 404 responses after creation.
