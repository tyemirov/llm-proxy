# Technical Documentation

Use concise, consistent American English for technical prose.
Apply formal ASD-STE100 rules only when the user or an applicable document contract explicitly requires compliance for the selected document or section.
For that scope, read `AGENTS.STE.md` and complete its reference and review gates.

## Meaning And Sources

- Preserve facts, requirements, product decisions, conditions, exceptions, and ownership boundaries.
- Keep assumptions separate from confirmed requirements and acceptance criteria.
- Record an unresolved product decision as an open decision rather than inventing a requirement.
- Preserve code, commands, paths, identifiers, URLs, quotations, proper names, legal text, and third-party text as source-controlled literals.
- Read repository terminology and use one term for each concept. Define necessary new technical terms.

## Writing And Review

- State the action, condition, and expected result when they control execution.
- Prefer direct verbs, active voice, and sentences that carry one clear idea.
- Separate requirements from preferences and examples.
- Give each shared rule one authoritative location and explicit reading conditions.
- Review changed prose against its sources and the authorized scope. Check links, commands, and applicable document structure.
- Run repository document checks that apply to the change. Use the formal language checker only for selected STE scope.
- Report remaining uncertainty and the scope actually reviewed. A mechanical check does not prove factual accuracy.
